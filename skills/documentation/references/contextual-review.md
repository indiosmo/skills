# Reviewing a document in context

A useful page fits the surrounding documentation. After the editorial pass,
inspect its parent, siblings, children and relevant reference pages. Use the
contract to keep the selected document or related group explicit while recording
broader findings.

## Check ownership and connections

Compare terminology, version scope and substantive claims. Identify contradictory
instructions, repeated explanations, competing definitions and missing entry
points. Keep a fact where it is maintained most effectively and provide the
context a directly arriving reader needs. A short procedure prerequisite can
repeat a necessary fact while linking its maintained reference.

For example, if a parent says empty input yields `0` and a selected page promises
an exception, inspect current implementation and tests before choosing the
correction. If both pages repeat a lengthy newline explanation, retain it in the
explanation page and link from the procedure at the useful point.

Check whether a new page needs a navigation entry, a backlink from its parent,
a related task link or a reference-to-explanation link. Add "see also" material
only when it answers a plausible next question. An analogy should clarify a
specific relationship and state any limit necessary to prevent a false inference.
Verify its underlying claims like other explanation content.

## Record related edits

For each finding, identify the affected page and exact text, supporting evidence,
reader impact and proposed edit. Distinguish corrections needed for the selected
page to work from independent improvements. Apply authorized related fixes and
record broader follow-up work without silently expanding the document group.
Recheck navigation and links after moves or heading changes, then rerun affected
validation. Use [the review record](../templates/review-findings.md) to preserve
this rationale for the reviewer.
