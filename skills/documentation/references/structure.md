# Outlining a page or related group

An outline connects the document contract to the reader's path through the
material. Begin with the success condition and evidence, then select the
[document type](document-types.md). Use the [outline template](../templates/outline.md)
to record headings, their purpose and the claims they need.

## Decide page boundaries

Keep one page when the reader can complete or consult the task coherently in one
place. Split when stages have distinct starting states, audiences or independently
useful outcomes, or when separate concepts interrupt the main task. Length is a
signal to inspect organization, not a fixed page-count rule.

For multipart work, name the group's outcome, order pages by prerequisites, and
show previous/next steps plus an entry page. Each page states its starting state
and outcome. Add navigation in the existing site and check links in both
directions. A reader arriving from search should understand where to begin.

## Add sections that serve the task

A procedure needs prerequisites, ordered actions and observable results. Include
branches where evidence supports different environments. Put warnings before
the consequential action, with the condition and practical response. Include
errors, recovery and cleanup where the procedure needs them. A lookup entry needs
consistent fields, units, constraints and errors; an explanation needs concepts,
relationships and evidence for rationale.

Connect related pages using a link that answers a likely next question. Explain
diagrams in surrounding prose and provide a text alternative appropriate to the
project's renderer. Accessible descriptions and useful heading hierarchy need
editorial review even when the build succeeds. See Google's
[accessibility guidance](https://developers.google.com/style/accessibility).

## Contrasting outlines

A tutorial for the line-count fixture can use "Prepare a sample", "Run the
counter", "Try an empty file" and "Continue learning". Each action has a visible
result in a prepared environment. A how-to for an experienced maintainer uses
"Before you begin", "Count a file" and "Resolve input errors", with branches for
actual operational conditions.

An argument reference uses "Synopsis", "Input encoding", "Output" and "Errors".
A long section on why text streams are useful would interrupt lookup; link an
explanation titled "How line counting treats newlines" with sections for the
model, examples, limitations and tradeoffs. Concise usage examples can stay in
the reference when they clarify its facts.
