Validation runner architecture decision matrix

Choose maintainable boundaries for documentation-validate 0.1.0. The tool executes ordered native checks and records versions, diagnostics and outcomes. Scores express engineering judgment: 5 is appealing, 3 is mixed and 1 is a serious cost. Equal weights expose the trade-offs; the scores are not benchmark measurements.

Assumptions

  • Compatibility: existing manifests, CLI output, report fields and exit statuses remain supported.
  • Execution: manifests provide ordered dependencies and arbitrary native argument arrays.
  • Policy scope: version readiness and native command outcomes are the two implemented validation policies.
  • Environment: consuming projects prepare tool binaries, dependencies and native configuration.

Decision

Use explicit modules. Pure version and command policies, a shared executor, ordered orchestration and reporting provide focused tests and contain policy changes. The additional navigation is proportionate to these existing responsibilities.

The static registration surface consists of explicit exports in validators/__init__.py. Direct typed calls expose each policy's inputs. Native tool families remain ordinary manifest checks.

Revisit plugin discovery when validators need independent distribution; revisit scheduling when measured pipeline duration justifies concurrent execution.

The architecture guide maps modules, explains extension steps and cites the primary research behind these boundaries.
